# 朗读

把聊天里的文字念出来。默认走微软的**神经网络语音**（晓晓 / 云希等，和 Edge「大声朗读」同一音源家族），由本机一个小服务合成，再经 DSH 自己的 HTTP 端口**同源**转发给页面；服务不可用时自动退回浏览器自带语音（慧慧）。

## 用法

1. **念选中的一段**：在已完成的回复里选中文字，选区上方出现浮动操作条，点「🔊 朗读选中」。
2. **念整条回复**：在回复里任意位置右键，出现同一条操作条，点「📄 朗读整条」；也可以先选中一小段再点「整条」。
3. **停止**：朗读时第一个按钮变成「⏹ 停止朗读」。
4. **换音色**：点「🗣 晓晓」在 晓晓 / 晓伊 / 云希 / 云健 / 云扬 / 晓北 之间循环，选择记在浏览器本地。
5. **换语速**：点「1×」在 0.75 / 1 / 1.25 / 1.5 倍之间循环。

**看音色按钮就知道走的哪条路**：显示「晓晓」等名字＝神经网络语音生效；显示「内置语音」＝已退回浏览器语音（控制台会有 `[read-aloud]` 警告）。

## 链路

```
页面 → /read-aloud/tts（同源，DSH 的 HTTP 端口）
     → 宿主插件转发 → 127.0.0.1:17865（Python + edge-tts）→ 流式 mp3
```

- 同源转发是刻意的：浏览器不必跨端口请求，不会有 CORS、跨域播放或 CSP 的问题。
- 服务**流式**返回：合成出第一块音频就开始播，不等整段合成完；页面还会预加载下一段，段与段之间几乎不断。
- 第一段会先切出一个短句（约 120 字以内）优先播，降低开口延迟。
- 内部服务只绑定 `127.0.0.1:17865`；宿主半在 DSH 启动时拉起它，也可是手工启动：
  `python server/tts_server.py --port 17865`。
- 合成走微软在线 TTS，**需要联网**；断网时自动退回浏览器语音合成。

## 限制

- 只对已完成的 Assistant 文本、用户消息和 reasoning 生效；流式输出中的文字、工具卡片、注入上下文不参与。
- 「朗读整条」的「一条」是宿主标记的交互容器（`data-text-interaction-source`），通常是整条回复的正文块；如果该块只包含一段，就只念这一段。
- 单次请求的文本上限：服务侧 4000 字，页面按 600 字切段（中文经 URL 编码会膨胀约 9 倍，600 字仍在 HTTP 请求行长度限制内）。
- 只读聊天文本；侧边栏里的文件预览目前不能朗读。
- 第一次开口约有 0.6–1.2 秒的合成延迟（微软在线合成所需），之后是连续播放。
